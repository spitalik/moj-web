# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`moj-web` is a collection of **independent, zero-build static PWAs**, each in its own top-level folder. There is no package.json, bundler or transpiler anywhere: everything is hand-written vanilla HTML/CSS/JS served as static files. The repo is published as-is on GitHub Pages, so each app lives at `https://spitalik.github.io/moj-web/<folder>/`.

The root `index.html` is only a placeholder link page. Root `tools/` holds old one-off Python scripts for a former `gamepad/` layout that no longer exists; they are not used by any current app.

**Every app is fully self-contained in its own folder** and must stay that way: its fonts, libraries, icons, sounds, translations and tools live inside that folder (fonts in `fonts/` or `vendor/fonts/`, libraries in `vendor/`). Never reference a file outside the app's folder (no `../` out of it, no root-absolute `/…` paths, nothing from the repo root) and never share files between apps. If two apps need the same font or library, each gets its own copy, together with its licence file. Each app has its own `index.html`, `sw.js`, manifest, `icons/` and (where needed) `tools/`. Always reference files by their full path from the repo root, because names like `index.html`, `sw.js` and `tools/test.js` exist in several apps.

The developer is Slovak-speaking: UI texts, code comments and commit messages are mostly in Slovak.

## Running / developing

Serve the repo root over HTTP (service workers and manifests need a real origin, not `file://`):

```
python -m http.server 8000     # then open http://localhost:8000/<folder>/
```

`.claude/launch.json` defines this server as `static` for the Claude browser preview.

**When testing, bypass the service worker cache** (DevTools → Application → Service Workers → "Update on reload", or unregister the worker), otherwise you may see an old cached version.

### Checks per app (run from the app's folder)

- `math/`: `node tools/validate.js` (content, generators, translations; `--lang <code>` for one language). After changing lessons or translations run `node tools/index_build.js` (or `tools/i18n_build.js`, which calls it); `validate.js` fails if the index is stale. CI runs the validator per language: `.github/workflows/math-validate.yml`.
- `phys/`: `node tools/validate.js` and `node tools/index_build.js`, same as `math/`.
- `juro/`: `node tools/test.js`.
- `sleep-detective-app/`: `node tools/test.js` runs the detector tests (`sound.js` on synthetic sound) and then `tools/test-app.js`, a scenario test of the whole app (`app.js` as loaded by `index.html`) with a fake DOM, clock, microphone and IndexedDB. Add a scenario there for every new feature. **Security:** `index.html` has a strict Content-Security-Policy (scripts only from the app's own files, no connections to other servers), so all code lives in `app.js`/`boot.js`, never in an inline `<script>`; the test fails if `index.html` contains one or lacks the CSP. Data from storage and from a restored backup goes through `cleanData()` (expected shape only, strings stripped of `<`, `>`, `&`, quotes, backticks and backslashes), and closed experiments are escaped when shown; the scenario "bezpečnosť: podvrhnutá záloha…" restores a hostile backup. **Texts and languages:** no user-facing text is written in `index.html` or `app.js`; every text is a key in `i18n/sk.js` (the Slovak source) and is read with `L(key, vars)` or, for counts, `Ln(key, n, vars)` (plural forms `{ one, few, many, other }` chosen by `Intl.PluralRules`). `i18n/core.js` is the engine (`SDI18N`), and `i18n/<code>.js` holds the 12 languages (sk, en, es, pt, de, fr, it, ru, tr, ja, ko, zh) with identical keys. A new or changed text must be added to **all 12** files; the app test checks that every dictionary has the same keys, placeholders and list lengths. The language is chosen in Settings (`SET.lang`); a fresh install starts in English (`SDI18N.DEFAULT`). Dates and decimals follow the language (`Intl`, `_dec`). Stored data contains no texts: experiment results are saved as numbers (`r`) and their text is built when shown. The scenario tests run in Slovak (the harness sets `lang: "sk"` unless a test turns `forceSk` off). `tools/zaloha-test-7dni.json` is a sample backup for testing "Obnoviť zo zálohy". Native app (appId `sk.sleepdetective.app`): `node tools/build_www.js && npx cap sync`, then `gradlew assembleDebug` in `android/` (needs `android/local.properties` with `sdk.dir`), output `android/app/build/outputs/apk/debug/sleep-detective.apk`; iOS is built in Xcode on a Mac (`npx cap open ios`). After changing the icon run `python tools/make_icons.py`, which also regenerates the native icons and splash screens. In the native app `NATIVE` is true: files are shared via Filesystem + Share instead of downloaded, KeepAwake holds the screen on, the App plugin handles the Android back button, and no service worker or install card is used. Background recording on Android: the app's own plugin `BackgroundRecording` (`android/app/src/main/java/sk/sleepdetective/app/BackgroundRecordingPlugin.java`, registered in `MainActivity`) starts `RecordingService`, a foreground service of type microphone with a persistent notification (its texts are passed from JS in the app language) and a partial wake lock. **On Android the service itself listens** (`NightCapture.java`: `AudioRecord` at 16 kHz, read once a second without blocking because every `read()` costs about 1 ms of CPU; for each 100 ms tick the same level and low-ratio maths as `sound.js` over the last 512 samples (32 ms), kept for the whole night; this costs about 0.6 % CPU with the screen off, `status()` reports `busyMs`/`readMs`): the WebView renderer is an isolated process that the battery exemption does not cover, and HyperOS kills it with the screen off when it uses more than 2 % CPU (`ScreenOffCPUCheckKill` in logcat); just passing microphone audio into the WebView costs about 3 %. `app.js` (`pollNative()`/`feedNative()`/`feedTick()`) fetches the ticks in batches via `drain({from})` (every second with the screen on, otherwise every 10 s) and runs the normal detector on them; samples and full-night parts are encoded to AAC `.m4a` by the service (`AacWriter.java`, `clip({from,to})` from the last 4 minutes held in memory, `segment({t})`, files in the app cache until fetched; with recordings turned off no sound is held at all). If the system kills the WebView process, `MainActivity` recreates the activity instead of letting the whole app die, and `resumeNative()` picks the running night up again (replays all ticks, keeps the samples already saved). While the service runs, `NightWebView` (the app's WebView subclass, swapped in by `android/app/src/main/res/layout/capacitor_bridge_layout_main.xml`) does not tell Chromium that the window was hidden, so the page keeps fetching. Without that service (web PWA, an old plugin or a microphone the service cannot open) sound is read in the WebView: straight from the microphone with `MediaStreamTrackProcessor` (`startDirect()`, spectrum by `SleepSound.spectrumDb()`), or Web Audio (`startWebAudio()`, AudioWorklet or timer) as the last fallback; Web Audio only runs while its silent speaker output runs, which Xiaomi's PowerKeeper pauses about a minute after the screen turns off (`pause zero data process`), and it resumes the AudioContext whenever the system suspends it. Some vendors (Xiaomi, Huawei, Oppo, Vivo, Samsung…) still put the app to sleep, which no app can prevent; so before the first recording (`withPower()`, remembered in `SET.powerAsked`), in Settings and in the morning report after a gap the app offers `fixPower()`: the plugin's `askBattery()` (system dialog, permission `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) and `vendorSettings()` (the vendor's battery/autostart screen, falling back to app info; the packages are listed in `<queries>` in the manifest). With it running, KeepAwake is not used; if it fails, the app falls back to keeping the screen on. iOS and the web PWA cannot record in the background.

## Rules that apply to every app

- **Bump the `CACHE` version in that app's `sw.js` on essentially any change** to its files (for example `sleep-detective-v17` → `-v18`). Without it, returning users keep getting the cached old version. New files the app needs offline must also be added to the `ASSETS` list in `sw.js`.
- **Licences, GDPR and other law must not be violated.**
  - Only use libraries, fonts, icons, sounds and images whose licence allows it, and ship the required licence/attribution files. Existing records: `jocadium-app/NOTICE`, `math/THIRD-PARTY-NOTICES.md`, `phys/THIRD-PARTY-NOTICES.md`, `juro/THIRD-PARTY-NOTICES.md`, `sleep-detective-app/fonts/OFL-*.txt`, `blood-pressure-app/fonts/OFL-*.txt`, `universal-tuner-app/fonts/OFL-*.txt`. Every app has its own `LICENSE`.
  - Do not copy protected content, names or look of existing games or brands.
  - **Nothing may be loaded from third-party servers at runtime** (no Google Fonts, CDNs, analytics or trackers), because that sends the user's IP address to the third party. Bundle fonts and libraries inside the app (fonts as `fonts/*.woff2` + `fonts/fonts.css`, libraries in `vendor/`).
  - Keep user data on the device (localStorage / IndexedDB), collect only what the feature needs, tell the user what is stored, and let them export and fully delete it. This matters most for `sleep-detective-app/`, which records audio in the bedroom and stores health-related data. Its "Ochrana súkromia" screen (`openPrivacy()` in `sleep-detective-app/app.js`) lists what is stored and for how long: update it whenever that changes.
- **Security check on every change.** Apps run untrusted input (backup/import files, data already in localStorage or IndexedDB, URL parameters, file names, user-typed text). Before finishing a change, check it:
  - Never put untrusted text into `innerHTML` or an HTML attribute without escaping it (`esc()` or `textContent`); do not use `eval`, `new Function` or string `setTimeout` on data.
  - Validate imported or restored data before using it: expected types and shape, dates as `YYYY-MM-DD`, keys only from known values, no `__proto__`. Treat data already in storage the same way, because it may come from an older import.
  - No inline `<script>` or `on…=` handlers in new code, so a Content-Security-Policy can forbid them; new apps should get a CSP `<meta>` like `sleep-detective-app/index.html` (no third-party origins, `connect-src 'self'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`).
  - Native wrappers: keep `android:allowBackup="false"`, components `exported="false"` unless they must be public, and request only the permissions the feature needs.
  - Add a test with hostile input (for example a tampered backup) when a change reads external data, and mention any remaining risk to the user.
- Apps are used mainly on Android phones as installed PWAs: support touch, small screens and offline use.
